## 2026-10-10 — Task 0.2 PDF spike

- **pdfrx 2.6.5 for PDF rendering** (MIT; uses Google's PDFium, BSD-style licence). At build time it downloads prebuilt PDFium binaries from github.com/bblanchon/pdfium-binaries. The app makes no network calls with it at runtime.

Stored annotations must not depend on the PDF library (CLAUDE.md rule 3), and Windows needs to reuse it. Positions are stored in unrotated PDF points (origin bottom-left), which is what an exported PDF will need.
- **CI also builds a release-mode APK.** Flutter debug builds are much slower than real use, so the smoothness verdict must come from the release APK. It is signed with a throwaway CI debug key, and no real signing key is involved.
- **Sample PDF generated by `tool/make_sample_pdf.py`** (300 pages, 1.8 MB, standard library only) and committed as an asset. It has rotated and landscape pages to test alignment, and printed target boxes to compare against the overlay.

## 2026-10-10 — Feedback from the task 0.2 tablet test

- **Owner's local time zone** for build stamps and dates (owner's choice). The CI workflow sets `TZ` from the private `BUILD_TZ` secret, and each APK shows its build time on the home screen; file and artifact names use the build number only.
- **CI builds only a release APK for 64-bit ARM** (owner's choice). This cuts build time and disk use for the GitHub Free plan. The debug APK is dropped: the owner tests release builds, and `flutter analyze` and `flutter test` still run on every PR. Docs-only changes skip CI.
- **Conventions in CLAUDE.md:** tooltips on all icon buttons, and a loading indicator or progress bar for anything slow.
- **Our own PDF importer instead of `file_picker`.** `file_picker` copied the whole file before returning, with no progress, so a very large PDF froze the app for about 20 s. `PdfImporter.kt` opens Android's system picker itself and copies the file in the background in 1 MB chunks. It reports progress, so the app can show a progress bar, time remaining and a Cancel button. The original file is only read, never changed. Copies live in the app's cache (`cache/imports`). Opening the same file again is instant, and only the 3 most recent imports are kept, to cap storage use. Android may clear the cache when storage is low; the file is then simply imported again. Task 1.1 will decide how the real PDF library stores files. This removes the `file_picker` dependency.
- **Scroll bar:** pdfrx's built-in `PdfViewerScrollThumb`, sized for a finger or stylus, showing the current page number.

- **Messages float, leaving a 96 px gap on the right**, so they never cover the scroll tab.

## 2026-10-10 — Task 0.3 foundations

- **Storage: `sqflite`** (BSD-2) rather than `drift`. It's simple, mature and needs no code generation, so CI stays lean, and our queries are few and simple. The database is `writing_recogniser.db` with versioned migrations (`lib/storage/app_database.dart`). Tests run the real SQL using `sqflite_common_ffi` (BSD-2; dev-only, not in the app). The Windows build can use the same FFI version later. Behind a pure-Dart `SampleStore` interface.
- **Ink model** (`lib/core/ink.dart`, pure Dart): every point keeps x, y, time (ms since epoch) and pressure (0–1), as rule 4 requires. It's stored as compact JSON arrays.
- **Recognizer interface** (`lib/core/recognition/recognizer.dart`): `recognize(strokes, context) -> List<Candidate>`, plus `status()`/`prepare()` for one-time setup (model download, keys). It also says whether the engine works on-device or in the cloud.
- **The canvas is pen-only**, and the pen's side button or eraser end erases whole strokes (owner decisions below). The eraser measures distance to the lines between points, not just to the points, so quick strokes are caught.

## 2026-10-11 — Task 0.3 ML Kit engine

- **`google_mlkit_digital_ink_recognition` 0.16.1** (MIT; network use approved by the owner for the one-time model download only). It's used only in `lib/recognition/mlkit_recognizer.dart` (rule 1). The app prefers the device's own English variant, then en-GB, en-US and en, using the first one ML Kit offers. The download is allowed over mobile data (about 20 MB; the button says so). ML Kit doesn't report download progress, so the screen shows a moving bar and the seconds elapsed instead of a time estimate.
- **Live recognition recognises everything on the writing area** after the pause (0.8 s by default, adjustable in Settings → Handwriting). Grouping into words and lines is task 2.2. If you write again during the pause, it waits for the new stroke. A slower, older answer is ignored if a newer one has already been requested.
- **Latency = time from the pen lifting to the text appearing**, measured from the last stroke's end time.
- **Event log started (rule 5):** SQLite `events` table (database version 2; older databases upgrade automatically and keep their samples). Each recognition logs the engine, latency, top guess, number of guesses and strokes, and the pause setting. It stays on the tablet.

## 2026-10-11 — Task 0.3 MyScript Cloud engine

- **MyScript iink Cloud via the REST "batch" API** (`https://cloud.myscript.com/api/v4.0/iink/batch`), worked out from MyScript's open-source iinkTS client (Apache-2.0); their documentation site isn't reachable from the development environment. Requests are signed with HMAC-SHA512 (key = application key + HMAC key), checked against Python's standard implementation in the tests. It asks for text recognition in British English, falling back to US English, and JIIX output with per-word alternatives. "Other guesses" are built by swapping in each word's next-best reading.
- **Only pen strokes are sent** (points, times, pressure, writing-area size) and nothing else. The owner approved this for the test/GATE A. Each engine is labelled in the app as "runs on this tablet" or "sends pen strokes to a server".
- **Keys are entered by the owner on the tablet** (Settings → MyScript Cloud). They're stored in the app's private storage (`shared_preferences`) and never in the repo. That's acceptable for a test build; if MyScript is kept, move them to Android's encrypted storage.
- **New packages:** `http` 1.6.0 and `crypto` 3.0.7 (both BSD-3, Dart team).
- **Android INTERNET permission added.** Release builds have no network access without it, so both the ML Kit model download and MyScript Cloud need it. Those two are the only owner-approved network uses.
- For later: MyScript accepts a **custom word list** (`customLexicon`), which could feed the owner's corrected words straight to the engine (Phase 2).

## 2026-10-11 — GATE A report tools

- **Accuracy is measured as character error rate (CER) and word error rate (WER)**: the edit distance between what was written and the top guess, divided by length and weighted across all samples. Two readings: **lenient** (ignores capital letters, punctuation and extra spaces; closest to "did it get the words right") and **strict** (everything counts). Also reported: the share of perfectly recognised samples.
- **Speed:** engine time per sample (median and 90th percentile) when replaying samples, plus live pen-lift-to-text times from the event log.
- **"Copy report"** puts a plain-text summary on the clipboard for the owner to paste into the chat at GATE A. Each run is also logged (`evaluation` events) on the tablet.

## 2026-10-11 — Start ML Kit ourselves; record crashes on the tablet

**Decision:** Switch off ML Kit's automatic start-up (`MlKitInitProvider`) and start it from `App.kt` inside a try/catch. Record any crash to a file and show it on the next launch with a Copy button.

**Reason:** The first build with ML Kit closed at launch on the owner's tablet. ML Kit's start-up runs before the app's first screen, so a failure there takes the whole app down, and there was no way to read the tablet's logs. Now ML Kit failing only disables the ML Kit engine (with its error shown), and any other crash can be copied and pasted back.

## 2026-10-11 — Sample backups; pen side button

- **Backups:** Saved samples → Back up writes every sample to one file the user saves anywhere through Android's file picker (Downloads, Drive, USB...). It is gzip-compressed JSON (`handwriting-samples-YYYYMMDD-HHMM.json.gz`) holding text, strokes (x, y, time, pressure) and canvas size, and the file describes its own units. **Restore** reads it back and skips samples already present. No new packages: dart:io gzip plus a small Kotlin file-picker bridge (`FileTransfer.kt`). Reason: the owner wants users to be able to back up their data, and the same file can later feed evaluation or model work.
- **Collecting users' samples for model improvement is not built.** For now a user can send their backup file by choice. Any automatic or in-app sharing needs the owner's decision first (CLAUDE.md rule 7: opt-in, consent wording, where the data goes).
- **Pen side button:** some styluses report it as the stylus *primary* button; the canvas only checked the secondary one. Both now erase, including when the button is pressed mid-stroke.

## 2026-10-11 — Signing key: one-time workflow (owner chose option a)

A manual workflow, "Create signing key (run once)", makes the owner's permanent signing key on GitHub's machine and offers it as a one-day download. The owner adds it as the `ANDROID_KEYSTORE_BASE64` and `ANDROID_KEYSTORE_PASSWORD` secrets and keeps a copy safe; CI then signs every build with it, so updates install over the previous version and keep the app's data. The key is never committed. Reason: a test build's samples were lost because each build had a different throwaway key. **Removed when the repo went public:** in a public repo that download would be open to anyone, and the key already exists.

## 2026-10-11 — Launch check in CI; Phase 1 choices (owner)

Reason: two builds crashed at launch on the tablet and the build machine only checked that the app *built*. Adds about 5–8 minutes per build.
- **PDF export uses PDFium** (the engine pdfrx already uses; free, keeps the original text selectable, ink stays sharp). Not Syncfusion (commercial licence) or page images (loses text, large files).
- **Straight lines: hold to snap** (note-app style): keep the pen still about 0.5 s at the end of a stroke and it straightens.
- **Toolbar like common note apps:** a fixed pen toolbar the user can move between the top and the side, plus a floating favourites bar where the user pins specific pens (type, colour, width).

## 2026-10-11 — Task 1.1a: real viewer replaces the spike screen

The task 0.2 spike screen (tap dots, "Clear dots") is replaced by `lib/viewer/pdf_viewer_screen.dart`: page number with **Go to page**, the same scroll tab and opening banner, and each PDF reopens on the page where it was left. ## 2026-10-11 — Task 1.2a: writing on PDF pages

Each visible page gets an ink layer (`lib/viewer/page_ink_layer.dart`). A small gesture recogniser claims stylus pointers the moment they touch, so the pen writes while fingers still scroll and zoom (owner decision: pen writes, fingers scroll). Ink is converted to PDF page coordinates as it is written (`lib/core/page_ink.dart`, pure Dart), so it stays locked to the page at any zoom and rotation and can be saved (1.3) and exported (1.4) without depending on the screen. The side button or eraser end removes whole strokes for now; partial erase, pen tools, undo and saving follow in 1.2b–1.3.

## 2026-10-11 — Task 1.2b: pen tools, toolbar and favourites

- **Toolbar** (owner: like common note apps): Pen, Highlighter, Eraser, colour and size, pin to favourites, and a "Move the toolbar" menu (top, left side, right side). Tapping the selected pen again opens its colour and size, as in common note apps. The PDF keeps its place when the toolbar moves.
- **Favourites bar** (owner): a floating bar of pinned pens (tool, colour, width), up to 8; drag the handle to move it; tap a pen to use it; long-press to unpin.
- **Pressure:** pen width goes from 60% (light) to 140% (hard) of the set width. The highlighter has a fixed width, is see-through, and is multiplied over the page so printed text stays readable.
- The eraser (tool or pen button) still removes whole strokes; partial erase comes in 1.2c. Tools are remembered on the tablet (shared preferences key `pens.state`).

## 2026-10-11 — Task 1.2c: partial eraser

Owner: whole-stroke and partial erase, switchable. Tapping the selected Eraser opens its options: **Erase whole strokes** (default) or **Erase only where I rub**, and an eraser size. The same setting applies to the pen side button. Partial erase cuts strokes into pieces (long segments are subdivided first so cuts are precise) and keeps each piece's time, pressure and style. The eraser covers its whole path between pen events, so fast rubbing doesn't skip lines.

## 2026-10-11 — Task 1.2d: undo and redo

Undo and Redo buttons in the viewer's top bar. One step per stroke written and one per eraser gesture (pen down to pen up), whichever page it was on; up to 200 steps per open PDF. Writing a new stroke clears Redo. The history is kept while the PDF is open (not across closing it).

## 2026-10-11 — Task 1.2e: hold to snap, arrows

- **Hold to snap** (owner): keep the pen still (within 4 screen pixels) for 0.5 s while drawing and the stroke straightens, with a light vibration; until the pen lifts, the line's end follows the pen. Strokes shorter than 20 pixels never snap. Works for the pen and the highlighter (straight highlighting).
- **Arrows** (my interpretation, flagged in the PR): an **Arrowheads** switch on the toolbar makes pen strokes end with an arrowhead. Draw a curve for a curved arrow, or hold to snap for a straight one. The arrowhead follows the stroke's last part, so a small wobble at the end doesn't twist it. After a partial erase, only the piece that still has the original end keeps the arrowhead.
- Shape recognition (circles, boxes, ...) stays out of scope (CLAUDE.md).

## 2026-10-11 — MyScript offline (iink SDK) as a third engine

**Decision:** Add MyScript's on-device iink SDK (`com.myscript:iink` 4.5.1, Maven Central) as an engine next to ML Kit and MyScript Cloud (owner: keep all three for GATE A). It uses the iink "Recognizer" API (text only, no MyScript UI) through a Kotlin platform channel. British English files are used if MyScript offers them, otherwise US English.

**Reason:** The owner prefers MyScript, and the offline SDK runs entirely on the tablet: no internet, no quota, nothing leaves the device (CLAUDE.md rule 7).

**Certificate:** The owner's certificate is kept in the `MYSCRIPT_CERTIFICATE_JAVA` GitHub Actions secret. CI writes it into the build, and it is never committed (gitignored path, loaded by reflection so builds work without it). APKs contain it, so CI only publishes them inside a password-protected zip. Don't share APKs publicly.

**Licence:** MyScript Interactive Ink SDK licence (proprietary; free developer certificate). The recognition files are downloaded from MyScript at build time and not committed.

## 2026-10-11 — Stable signing key (owner's key added 2026-10-11)

Builds so far were signed with a throwaway debug key that CI creates fresh on every run, so Android treats each APK as a different publisher: a new build won't install over the previous one, and uninstalling first deletes the app's data (the owner's samples). CI and Gradle now use the owner's own key when the `ANDROID_KEYSTORE_BASE64` and `ANDROID_KEYSTORE_PASSWORD` secrets exist, and fall back to the throwaway key otherwise. The key itself is never committed (`*.jks`/`*.keystore` are ignored). How the key is created is the owner's choice; Claude may not generate secrets.

## 2026-10-11 — Launch check uses a test-only x86_64 build

The CI emulator (Android 16, x86_64) has no ARM translation, so it can't run the arm64 APK (Flutter fails to load with "is for EM_AARCH64 instead of EM_X86_64"). CI now also builds the same code for x86_64 (`APP_ABIS=x86_64`, `--target-platform android-x64`) only to run the launch check; it is not uploaded, and the owner's APK stays arm64-only. Adds a few minutes per build. The real tablet remains the final test.

## 2026-10-11 — Pen tools after a test build (owner)

- **Fingers always scroll and zoom.** pdfrx chose its text-selection style from whatever touched the screen last; after the pen, a one-finger drag selected text, so fingers could no longer scroll or zoom. The viewer now always uses the touch style (long-press to select text).
- **Colour shown on the tool icon.** The pen and highlighter icons are drawn in their current colour; the separate colour button is gone (tap the selected tool again for colour and size).
- **Eraser outline.** A ring the size of the eraser follows the pen while it hovers or erases (eraser tool, side button, or eraser end), so users see what will be erased.
- **Toolbar position moved to Settings** ("Pen toolbar"); it applies the next time a PDF opens.
- **Reading position saved on Back.** The library reloads straight away when leaving a PDF, before the viewer had saved, so a page reached less than a second before leaving wasn't kept.
- **Arrowheads ignore the lift-off flick.** When a pen stroke with an arrow ends, a sharp turn (over 45 degrees) in its last ~1.5 arrowhead lengths is treated as the pen flicking away and trimmed, so the head points along the line (a right-handed writer: leftward arrows curled as the pen lifted to the right).

## 2026-10-11 — Sample backups are .zip files (owner)

Backups are now a `.zip` holding one readable `samples.json` (same content as before), because a zip opens directly on Windows and Android. Uses the `archive` package (MIT), which the app already contained through the PDF viewer (pdfrx), so the app doesn't grow. Older `.json.gz` backups still restore.

## 2026-10-11 — Writing hand, writing box width, pressure strength (owner)

- **Writing hand and box width.** Settings → Handwriting: Right hand / Left hand, and the handwriting box's width (40–100%, default 67%). For a right hand the box sits on the left, leaving the right side empty, and the reverse for a left hand. Applies to the sample recorder and the handwriting test. Reason: a right-handed writer's words written near the right edge got less legible and were recognised worse. The box size is saved with each sample, so recognition and the per-sample report use the real box.
- **Pressure strength** (0–100%, default 100%): how much pressing harder thickens the line. 0% draws constant thickness, like most PDF apps. Only drawing changes; pressure is always recorded. Applies to the handwriting boxes and the PDF pen (PDF pen at 100%: 60–140% of the set width, as before).

## 2026-10-11 — Record pen hover with samples (owner)

While recording a sample, the app keeps where the pen hovers over the box without touching (x, y, time), from before the first stroke until Save, up to 30,000 points (about 3 minutes). It is saved with the sample (database v4: `samples.hover`, JSON `[[x, y, t], ...]`) and included in backups. Today's engines don't use it; it is kept for later tuning to the writer's hand movement between strokes (CLAUDE.md rule 4 spirit: keep raw input). Stays on the tablet like all samples. Not recorded for PDF ink yet.

## 2026-10-11 — Task 1.3a: saving ink (owner: "work on the next tasks")

Ink written on a PDF is saved in the app database (v5 table `page_ink`: one row per document page, strokes as JSON in PDF page coordinates, with tool, colour, width, pressure and arrow). The PDF file itself is never changed (CLAUDE.md rule 6). Saving happens 0.4 s after the last edit on a page (so one eraser swipe is one save), and at once when leaving the PDF or when the app goes to the background, where Android may close it without warning. Saved ink loads in the background when a PDF opens; anything written meanwhile goes on top, and Undo never removes saved ink. Saved strokes stay editable (erase, partial erase). Undo history starts empty each time a PDF opens. Still to do in 1.3b: annotated PDFs kept as permanent library copies (never trimmed by the storage limit), and what happens to ink when a copy is deleted.

## 2026-10-11 — Task 1.3b: PDFs with ink are kept; ink kept on delete by default (owner)

## 2026-10-11 — Security and privacy hardening for the public repo

After a review of everything published to the public repo (owner request):

- **CI output is public.** The job runs in UTC; artifact, zip and APK names use the build number. The local-time build label reaches the APK through a file, never a printed command, step output or env value (GitHub prints those in the public log). The apk-info check no longer prints the signing certificate's details. Rule recorded in CLAUDE.md.
- **CI supply chain.** Every action is pinned to a commit SHA. Checkout doesn't keep the GitHub token in `.git/config`. The signing key file is deleted once signing is done, the unprotected APK once it is zipped. The "Create signing key" workflow was removed (its download would be public).
- **App data stays on the device.** Android cloud backup is off for all app data (`data_extraction_rules.xml`); moving to a new tablet directly still works. Network: https only, system certificates only (`network_security_config.xml`).
- **MyScript Cloud keys are encrypted** with an AES-256-GCM key held in Android's hardware key store (`SecretBox.kt`). Keys saved by older builds in plain text are encrypted and removed on first use. On a new device (or if the key store is reset) the keys must be entered again. Where no secure store exists (tests, future platforms until they get one), keys aren't saved and the user is told.
- **Only the launcher entry is exported**; MainActivity can't be opened by other apps.
- **Privacy check** also catches device brands, certificate details, UTC offsets, tokens and API keys, hard-coded passwords, and files that must never be committed (keystores, APKs, certificates). Device brand mentions in code and docs were made generic.
- **SECURITY.md**: problems are reported privately through GitHub's vulnerability reporting.

## 2026-10-11 — Security best practices before publishing (owner request)

- **Opened files are size-limited:** a sample backup over 200 MB, or one that unpacks to over 400 MB (a "zip bomb"), is refused with a message instead of exhausting memory.
- **Key fields** turn off autocorrect, suggestions and keyboard learning, so keyboards never store or sync the MyScript keys.
- **CI checks itself:** `tool/security_check.sh` fails on unpinned actions, risky triggers (`pull_request_target`, `workflow_run`), `write-all` permissions and event text inside scripts. The privacy workflow also checks every new commit's message and author/committer emails (only no-reply addresses allowed).
- **APK zip password** must be at least 16 characters, and builds are kept 7 days.
- **CODEOWNERS:** every change needs the owner's review once branch protection requires it.
- **Not done (and why):** certificate pinning for MyScript Cloud (it would break when MyScript renews certificates, and https with system certificates already blocks interception); code obfuscation (the code is public anyway); Dependabot (it opens PRs on its own; owner to decide).

## 2026-10-12 — Converting handwriting to typed text (2.3b–2.3d, owner's choices)

Owner's answers: (1b) the handwriting is kept and the user can switch between ink and typed text; (2c) convert a lasso selection or a whole page; (3b) typed text sits where the handwriting is, sized to fit it, in the ink's colour; (4a) tapping typed text edits it, and the edit also teaches the learning layer like a correction; (5b) at export the user chooses ink, typed text or both; (6) Convert is undoable.

## 2026-10-16 — A reading pause that learns how the user writes (owner's approved idea 5)

Reading waits after the pen lifts. That wait now adapts to the user. Each time a stroke carries on the word before it (beside it on the same line, under half a letter apart), the pen-up time between the two is kept, up to the last 200. Once 20 have been seen, the pause aims just above nine in ten of them (×1.3, plus 0.15 s). It moves a quarter of the way at a time, so one odd pause doesn't swing it, and it stays between 0.4 and 2.5 s.
- The space between words, new lines and i-dots don't count, so only real mid-word pauses do.
- Only strokes the pen has just finished count. Moving, recolouring, undoing or erasing ink doesn't, and neither do two strokes on different pages.
- The learned pause is kept between sessions. It's saved when the PDF closes or the app is put away, not while writing, because saving settings redraws the whole app. Settings shows it: "Learn how long I pause" (on by default). Turning it off brings back the fixed slider.
- The handwriting test screen uses the same pause.

## 2026-10-16 — Learning what the user draws and what they write (owner's approved idea 7)

Each time the user marks ink "This isn't writing", or says ink is writing ("This is writing", "Read as one word"), the marked pen strokes teach a small personal model. It keeps five numbers per stroke and no ink: height, width and length compared with the letters on the page, how straight the stroke is, and its size in points. Letter size is measured only from writing that wasn't marked, and only on pages with at least 10 written strokes; on a page that's mostly a sketch, a circle would otherwise look letter-sized. When a later stroke closely matches examples from at least 3 separate marks, the newest ones, and they all agree, it's sorted their way. One mark adds at most 5 examples, so a single selection is never enough on its own and can't push out what was learned before. Arrows teach nothing, since they're always drawings and would teach that straight lines are. That happens before the existing second look at how strokes were sorted, so a mark like the user's own ticks or crosses stops being read as a letter.
- The newest marks win, so changing one's mind takes effect.
- Strokes the user marked themselves are never overridden.
- Up to 400 examples are kept on the tablet.

## 2026-10-16 — Writing around printed text, at any size (owner's choice: options A and B together)

The owner asked how the lag fix decides which ink to send, and pointed out that users write as small and as large as they please, in margins, around the PDF's printed text.
- **Sorting writing from drawing (A):** after a pause, the new strokes are sent with the whole of each line they're on, so a long sentence is never cut off. Ink within 3 letters of each new stroke is sent too, measured in the letters of that stroke's own line (or the nearest line, for a stroke that isn't on one). Tiny margin notes get a tiny border and big writing a big one. Each new stroke gets its own border, so two strokes far apart don't bring in the page between them. Zoom never matters: all of this is in page units.
- **Printed text (B):** each page's printed text positions are read from the PDF in the background the first time its writing is read (scanned pages have none, so they work as before). Three rules use them:
  - Writing on either side of printed text is two lines, two notes in the margins, even when big writing would otherwise reach across.
  - The exception is writing that carried straight on: its next stroke started within 8 s of the line's last one (owner: 5 to 10 s; first 15 s). Then it's one line however wide the printed text is, since only the free space between counts.
  - The words "just before" that help the engine come from the writing above in the same column, not from whatever is at that height elsewhere on the page. A note in one margin no longer takes a note in the other margin as its context, and writing below a printed paragraph starts fresh. A line follows the one above it when there are at most 6 of its letters of space between, so small writing on widely spaced lines keeps its context. Lines written at the same slant are measured across the slant.
- On a page of 1000 words, choosing the ink to send takes about 20 to 35 ms in the tests, and printed text adds little to grouping. Printed text is only looked at for lines a stroke is level with, so many margin notes beside a full printed page stay quick.
- Printed text is read when the page is first written on, so it's ready by the first pause.

## 2026-10-16 — Blank pages, and adding, copying, taking out and moving pages (owner's choice: like any notes app)

- **The PDF is never changed** (CLAUDE.md rule 6). Each document keeps its own list of the pages it shows, in order (a `page_layouts` table, database version 10). The list holds the PDF's own pages, copies of them, and blank pages of our own. No list means the PDF is shown as it is, exactly as before.
- **Every page has a lasting key.** The PDF's own pages keep their page number as their key, so everything saved before this change stays where it was. Pages of our own get keys from 1000001 up. Ink, recognised text and bookmarks are saved under each page's key, and the viewer counts pages as shown. Adding, moving or taking out a page only changes the list, never the saved ink.
- **Showing it:** the viewer puts the shown pages together as one document. The PDF's own pages come from its file and blank pages from a small blank PDF the app makes itself. The PDF's contents list still goes to the right pages.
- **Adding:** a "+" button ("Add a blank page after this one") adds a page the size of the current page. In "All pages", long-press a page to add a blank page after it, duplicate it with its ink, or take it out. The "Rearrange pages" button drags pages into order.
- **Taking a page out:** a page of our own, or a copy, is deleted with its ink. One of the PDF's own pages is only hidden: its ink is kept, and "Put back" in "All pages" shows it again where it was.
- **After a change**, everything is saved and the PDF opens again on the right page, on the same screen. Tracking pages that move while they're shown would touch every part of the viewer. Opening again keeps it simple and safe, at the cost of a moment's wait. Rearranging warns before deleting blank pages or copies that have ink.
- A page's key is never used again in that document, even after the page is deleted, so a new page can't pick up old ink.
- If the saved pages don't fit the PDF file (its number of pages changed) or can't be read, the PDF is shown as it is and pages can't be changed. The saved pages and their ink are kept as they were, not written over.
- **Export** puts the pages in the order shown first, then draws the ink, so blank pages and copies come out with their own ink. Picking pages and arranging an export count pages as shown.
- The last page left can't be taken out.

## 2026-10-16 — Paper for blank pages (owner's choice: plain, lined, squared, dotted, and lined to fit their writing)

- Adding a blank page asks for its paper, with a small picture of each. It starts on the paper used last. The page can go "after page N" or "at the end". In "All pages", a blank page's long-press menu has "Change paper".
- **Lined:** ruled lines 8 mm apart, like ordinary lined paper, starting one and a half lines down. **Squared** and **dotted:** a 5 mm grid.
- **Lined to fit your writing:** lines a little over twice the user's typical letter height, kept between 4 and 16 mm. The letter height comes from the writing on up to 8 pages of this document, and is remembered for documents with no writing yet; it's 8 mm until there's any.
- Paper is drawn by the app under the ink, in a soft blue-grey (night colours on dark pages). It isn't ink: it can't be erased or selected and is never read as writing. Exports draw it under the ink as thin lines and round dots.

## 2026-10-16 — What a page-by-page export leaves out, said in place

When pages are picked or arranged, or were added, moved or taken out in the app, the export makes a new PDF page by page. PDFium copies only the pages, so the PDF's contents list and fill-in form boxes don't come along. The export screen says so in a line of small text under "Pages" (owner: no extra box to click through). It doesn't show for a plain export of all pages, which keeps everything.
